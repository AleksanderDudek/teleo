# Teleo v1.0 (+ v1.1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Teleo — a local-first, zero-cost PWA that verifies spoken prayers/affirmations sentence by sentence (PL + EN), counts repetitions, and motivates with calm gamification — exactly as described in `docs/TELEO_SPEC.md`.

**Architecture:** Static React SPA (hash routing) served from GitHub Pages under `/teleo/`. All state lives in IndexedDB (Dexie). Pure, DOM-free domain modules (`segmenter`, `matcher`, `gamification`, `session`, `time`) hold every business rule and are unit-tested; thin DB-coupled services orchestrate them; React screens only render and dispatch. Speech-to-text sits behind a `SpeechEngine` interface (Web Speech API now, in-browser Whisper in v1.1).

**Tech Stack:** Vite 8 · React 19 · TypeScript 6 · react-router 8 (data mode, `createHashRouter`) · Tailwind CSS 4 · Zustand 5 · Dexie 4 + dexie-react-hooks · vite-plugin-pwa 1.x (Workbox 7) · i18next 26 + react-i18next 17 · Vitest 5 + jsdom + fake-indexeddb + Testing Library · Playwright (e2e) · oxlint · lucide-react · self-hosted variable fonts (@fontsource-variable).

**Adaptation note (plan format):** the executor of this plan is the same agent that wrote it, working unattended. Pure domain modules (the risky logic) are specified with full contracts and exhaustive test tables so they can be delegated to subagents and built test-first. UI tasks are specified by behaviour, files and acceptance checks rather than full code listings (writing the whole UI twice would add no safety).

## 0. Ground rules (from spec §0 + environment findings)

- Work stage by stage (§14). After each stage: `npm run lint && npm run build && npm run test -- --run`, then one commit per stage (`feat(stage-N): …`).
- Code, file names, comments, commits: English. UI text: only via i18n (`src/i18n/pl.json`, `src/i18n/en.json`) — never hard-coded in components.
- No paid services, API keys, trackers or external analytics. No runtime requests to third-party origins except (a) the browser's own Web Speech service and (b) opt-in Whisper model download from Hugging Face (v1.1).
- Every non-obvious choice gets an entry in `docs/DECISIONS.md`.
- Node 24 locally and in CI (Vitest 5 and react-router 8 require Node ≥ 22; spec's `node-version: 20` would fail).
- TypeScript 6 defaults `strict: true`; `erasableSyntaxOnly` is on → **no `enum`, no `namespace`, no parameter properties**; use string-literal unions and `as const` objects.
- IndexedDB cannot index booleans → boolean fields are stored but never declared as Dexie indexes.
- Do **not** push to GitHub or create a remote repository without the user's confirmation (public repo = publishing). Everything else is authorized.

### 2.2 Matcher (`src/domain/matcher/`)

```ts
export type MatchOp = 'match' | 'near' | 'missing' | 'extra' | 'wrong';
export interface OpEntry {
  op: MatchOp;
  source?: string;      // normalized source token (match/near/missing/wrong)
  spoken?: string;      // normalized spoken token (match/near/extra/wrong)
  sourceIndex?: number; // index into normalized source tokens
}
export type RejectReason = 'empty' | 'emptySource' | 'extra' | 'wrong' | 'coverage';
export interface MatchResult {
  accepted: boolean;
  coverage: number;      // (matched + near) / sourceWords, 0..1
  matched: number;       // exact matches
  near: number;          // tolerated STT errors (count toward coverage)
  missing: number; extra: number; wrong: number;
  ops: OpEntry[];
  bestAlternativeIndex: number; // -1 when no alternatives
  sourceWords: number;
  reason: RejectReason | null;  // null when accepted
  transcript: string;           // raw text of the chosen alternative
}
export interface EvaluateOptions { lang: Lang; strictness: Strictness; threshold?: number /* 0.95 */ }
export interface Token { text: string; rawStart: number; rawEnd: number } // raw = whitespace-split words
export type DiffStatus = 'match' | 'near' | 'missing' | 'wrong' | 'none';
export type DiffPart =
  | { kind: 'source'; text: string; status: DiffStatus }
  | { kind: 'spoken'; text: string; status: 'extra' | 'wrong' };

export function normalize(text: string, lang: Lang): Token[];
export function removeFillers(tokens: Token[], lang: Lang, keep: ReadonlySet<string>): Token[];
export function stripDiacritics(word: string): string;
export function levenshtein(a: string, b: string): number;
export function compareWords(source: string, spoken: string): 'match' | 'near' | 'none';
export function align(source: readonly string[], spoken: readonly string[]): { ops: OpEntry[]; cost: number };
export function evaluate(source: string, alternatives: readonly string[], options: EvaluateOptions): MatchResult;
export function buildDiff(source: string, lang: Lang, result: MatchResult): DiffPart[];
```

Normalization pipeline (both sides): NFC → `toLocaleLowerCase(lang)` → unify apostrophes (`’‘ʼ´\``→`'`) → drop thousands separators inside digit groups (`1,000`→`1000`) → replace every char that is not letter/number/apostrophe/whitespace with a space (hyphens/dashes become spaces) → split to raw-indexed tokens → EN: expand contractions (`i'm→i am`, `don't→do not`, `can't→cannot`, `won't→will not`, `shan't→shall not`, `let's→let us`, pronoun+`'s` (it/that/what/there/here/he/she/who/where/how) → `is`, `'re→are`, `'ve→have`, `'ll→will`, `'d→would`, generic `n't→not`) → strip remaining apostrophes → merge `can not`→`cannot`, `for ever`→`forever` (EN) → digits canonical (`007`→`7`) → number words PL/EN 0–1000 (basic forms, greedy) to digits → tokens. Transcript only: remove fillers (PL `y+{2,}`, `e{2,}`, `h*m{2,}`/`hm+`; EN `u+m+`, `u+h+`, `e+r+`, `h+m+`, `m{2,}`) **unless the token also occurs in the source**.

Word comparison: `match` if equal; else compare diacritic-stripped forms: equal → `near`; else if both stripped lengths ≥ 4 and `1 - lev/maxLen ≥ 0.8` → `near`; else `none`.

Alignment: word-level DP with costs match 0, near 0.2, missing 1, extra 1, wrong 1.5; backtrack preferring diagonal, then missing, then extra.

Acceptance: strict → `extra == 0 && wrong == 0 && (matched+near)*100 >= 95*sourceWords` (integer arithmetic, no float edge cases). Lenient → wrong counts as missing (does not reject), extra still rejects. Evaluate every alternative, pick best by: accepted > higher coverage > fewer (extra+wrong) > lower cost > lower index. Empty (after normalization + filler removal) → `reason: 'empty'`.

Mandatory tests = spec §6.6 table (13 rows) + the extras listed in Task 2.2.

Semantics locked in DECISIONS.md: streak = number of **active** days in the current chain; frozen days bridge gaps but add nothing; chain may end today or yesterday (then `atRisk`). Freezes: +1 each time the streak reaches a multiple of 7 (cap 2); on app open, a gap of missed days is bridged only if `gap ≤ freezes` and the chain before the gap is non-empty (otherwise the streak breaks and freezes are kept). Comeback: first activity of a day with ≥ 3 full idle days since the last active day. Morning: accepted segment at local hour ∈ [dayStart, 8). Evening: local hour ≥ 21 or < dayStart. Weekly rhythm: ISO weeks (Mon–Sun) with ≥ 5 active days, longest consecutive run. Text flawless: multi-segment text → ≥ 1 perfect run (every segment first try in one block); single-segment text → best run of consecutive first-try accepts ≥ 10.

## Stage 1 — Data & content

### Task 1.1 (Lane C): `countWords`, `dayKey`, segmenter — TDD
Test tables (write first, see they fail, implement, see them pass):

`countWords`: `'Jestem spokojny i pewny siebie.'`→5 · `'  a  b '`→2 · `'— – ,'`→0 · `"I'm here"`→2 · `'Mam 10 celów.'`→3.

`dayKeyFor` (dayStartHour 3, local TZ): 2026-03-10 10:00 → `2026-03-10`; 2026-03-10 00:30 → `2026-03-09`; 02:59 → previous day; 03:00 → same day; start 0 → plain local date. `addDays('2026-12-31', 1)`→`2027-01-01`; `addDays('2026-03-01', -1)`→`2026-02-28`; `diffDays('2026-03-30','2026-03-28')`→2 (across DST change); `isoWeekKey('2026-01-01')`→`2026-W01`; `isoWeekKey('2027-01-01')`→`2026-W53`; `isoWeekday('2026-09-28')`→1.

`splitIntoSegments` (sentence):
- `'Ojcze nasz. Chleba naszego.'` (pl) → 2 segments.
- `'Pójdę np. do domu. Potem wrócę.'` → 2 (abbreviation protected).
- `'Modlił się św. Józef. Amen.'` → 2 (`św.` protected before capital).
- `'Mr. Smith is here. He is calm.'` (en) → 2; `'Use e.g. this. Then that.'` → 2.
- `'Czy to prawda? Tak! Na pewno…'` → 3.
- Paragraph break (`\n\n`) is a hard boundary even without punctuation; single `\n` joins with a space.
- Leading/trailing whitespace trimmed, empties dropped; `''` → `[]`.
- Fallback path (no `Intl.Segmenter`) produces the same results for the cases above.

`splitIntoSegments` (line): `'Jestem spokojny.\n\n- Jestem silny\n2. Jestem wdzięczny'` → `['Jestem spokojny.', 'Jestem silny', 'Jestem wdzięczny']` (bullets and `1.`/`1)` numbering stripped).

`analyzeSegments`: 41-word → `long` with split suggestion; 81-word → `tooLong`; `['Chwała Ojcu i Synowi.', 'Amen.']` → `short` (index 1, mergeWith previous); `['Amen.', 'Chwała Ojcu i Synowi.']` → `short` (index 0, mergeWith next); `'Mam 10 celów.'` → `digits`; 151 segments → `tooMany`.
`suggestSplitPoint`: prefers `;`/`:` nearest the middle, then `,`, else middle word; returns null for ≤ 1 word.
`splitSegmentAt` / `mergeWithNext` / `replaceSegment`: pure, immutable, bounds-checked (throw `RangeError`).
